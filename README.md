# bethero — NPB 量化投注分析引擎

專門分析日本職棒 (NPB) 讓分盤與大小分的量化投注代理人。
刻意 **不** 沿用 MLB 的得分環境與模型參數。

## 設計原則

這個專案最重要的性質不是模型多準，而是 **資料不足時不會給出建議**。

`bethero.gates.grade()` 是唯一能產生「推薦」的出口，而它要求:

| 門檻 | 條件 |
|---|---|
| 模型 EV | ≥ +4% |
| 模型 vs 市場去水後機率 | ≥ 3 個百分點 |
| 盤型與結算規則 | 已確認 |
| 預告先發 | 已確認 |
| 正式先發打線 | 已公布 |
| 資料完整度 | 軟性缺口 ≤ 2 項 |

任何一項沒過，最好的結果是「觀察」。空的 `DataReadiness()` 不論 EV
算出多少都不可能推薦 —— 這條性質有測試守著
(`test_no_data_cannot_produce_recommendation`)。

## 模組

| 模組 | 職責 |
|---|---|
| `bethero.lines` | 亞洲盤盤口解析 (`8平` / `7+25` / `7-25`) 與結算規則 |
| `bethero.board` | 看板辨識結果的資料結構，每欄帶信心度 |
| `bethero.model` | NPB 專屬得分分布模型 |
| `bethero.ev` | 去水 (比例法／次方法)、期望值、一般化 Kelly |
| `bethero.gates` | 推薦門檻 |
| `bethero.bankroll` | 本金、單注上限、單日曝險上限 |
| `bethero.report` | 繁體中文報告輸出 |
| `config.npb_priors` | 先驗參數 + **校準狀態** + 已知偏誤 |

## 盤口解析

看板用 `平` 這個記號錨定整數盤，因此 `+` / `-` 是相對整數的 **位移**:

```
8平   -> 8.00        7+25 -> 7.25        7-25 -> 6.75
```

這個推論對 **大小分欄位完全自洽**。但讓分欄常出現 `1-60` / `1+80` /
`1+95`，位移後不落在 0.25 級距上。解析器不會四捨五入去猜，
而是標成 `UNCONFIRMED` 並附上原因，由 `gates` 擋掉。

結算規則 (`settle_handicap` / `settle_total`):

* 整數盤 —— 剛好打平走盤退回
* 半球盤 —— 無走盤
* 0.25 / 0.75 盤 —— 注碼各半掛在相鄰兩腳，會出現半贏／半輸

## 得分模型

每隊期望得分 `lam = league_rpg × off × opp_def × park × weather × home_edge`，
得分分布用 **共享環境因子的 Poisson 混合**:

```
G ~ Gamma(k, 1/k)          # 全場共用的「今天好不好打」
R_home ~ Poisson(lam_home × G)
R_away ~ Poisson(lam_away × G)
```

積分掉 `G` 之後每隊邊際分布是負二項 (捕捉得分的過度離散)，
且兩隊得分正相關 —— 這正是球場、天氣、主審好球帶的效果。
用獨立 Poisson 會系統性低估大小分尾端。

NPB 專屬處理:

* 較低的得分環境 (單隊 ~3.85 分/場，非 MLB 的 ~4.5)
* **和局**: 延長至 12 局為止，和局有實質機率
* **主隊九局下領先就不打** —— 拆成前八局與九局下兩段條件式相加。
  用單一 lambda 打折會把主場優勢一起吃掉 (這是實作時踩到並修掉的 bug)
* 先發投球局數較長

## 已知偏誤 ⚠️

`config/npb_priors.py` 的 `KNOWN_BIASES` 有完整說明，最重要的一項:

> **九局和局率偏高**: 模型算出約 15-17%，NPB 實際約 9-10%。
> 這個偏誤對 `dispersion_k` 不敏感 (k 由 3 掃到 15 只從 17.1% 降到 15.0%)，
> 是 Poisson 系列得分模型的結構性問題。
>
> 後果: **整數讓分盤的走盤率被高估**，一分差比例也偏高
> (模型 40% vs 實際約 33-35%)。整數盤在校準前不可下注。

另外 `config/npb_priors.py` 中所有參數目前 `calibrated=False`。
這些是先驗，不是事實。

## 使用

```bash
python3 -m pytest -q                      # 78 項測試
python3 analysis/slate_2026_08_13.py      # 產生當日報告
```

## 風控

本金 100,000 單位／0.25 Kelly／單注上限 1,000 單位／
單日曝險上限 5%／不串關。

`ev._kelly` 用數值最大化 `E[log(1 + f·R)]`，而非課本的 `(bp-q)/b` ——
因為半贏／半輸的走盤盤口不是二元賭局，套二元公式會高估注碼。
